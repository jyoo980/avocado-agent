  Workflow discovered

  This CBMC 6.7.1 build's dfcc contract checker is broken — goto-instrument 
  --dfcc … --enforce-contract segfaults in nondet_static.cpp on any input. The
  working path is the non-dfcc enforce flow:
  goto-cc --function <fn> -o k.goto kilo.c
  goto-instrument --generate-function-body <syscall-stubs>
  --generate-function-body-options nondet-return \
                  --enforce-contract <fn> k.goto ke.goto
  cbmc ke.goto
  Genuine OS externals (tcsetattr, ioctl, read, write, fopen, …) are stubbed as
  nondet-return (a sound over-approximation) so "no body" doesn't spuriously
  fail, while CBMC's own libc models (memcpy, realloc, strchr, …) are left
  intact.

  Why the other 26 don't verify (all have contracts)

  - Loops (majority): the non-dfcc assigns-checker rejects any function whose
  body still contains a loop ("Loops remain … cannot be applied"). Loop
  invariants are forbidden by CLAUDE.md, and symbolic-size memmove/realloc can't
  be bounded without a hardcoded --unwind (also forbidden). This covers the
  row/editor/IO functions, directly or via inlined loopy callees.
  - Recursion: editorUpdateSyntax is recursive → inlining throws a numeric
  exception in goto-instrument; this cascades to its callers (editorUpdateRow,
  the editorRow* mutators, etc.).
  - is_separator: glibc isspace expands to __ctype_b_loc(), which has no CBMC
  body.
  - enableRawMode: writes errno, which is a function-call macro and is illegal
  as an assigns-clause target.
  - editorMoveCursor: CBMC flags a genuine latent out-of-bounds read
  (E.row[filerow-1] without checking filerow-1 < numrows).

  The C code was not modified except for inserting specifications.
